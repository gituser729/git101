# Git 101 beginner friendly

A one-hour, beginner-friendly workshop on Git, GitHub, and a first taste of Python. The session spends 15 minutes on Git concepts and 45 minutes on hands-on activities. No prior coding experience is needed.

## Student materials

- [Student handout](./student-handout.md): a quick reference and hands-on checklist.
- [Business case exercise](./business-case/README.md): the sample proposal students analyze.
- [Python market-test exercise](./business-case/pilot_check.py): a short script students run and modify.
- [Submission instructions](./submissions/README.md): the format for each student's individual proposal.

## Learning outcomes

By the end of the workshop, students should be able to:

1. Explain the difference between Git and GitHub.
2. Describe a repository, commit, branch, pull request, and merge in plain language.
3. Make and describe a change, propose it for review, and understand how it joins the shared project.
4. Modify a small Python script and explain how changing an assumption affects its output.
5. Explain how a visible change history supports teamwork and accountability.

## At a glance

| Time | Activity |
| --- | --- |
| 0–5 min | Why teams need a reliable change history |
| 5–10 min | Git, GitHub, repositories, commits, and history |
| 10–15 min | Branches, pull requests, and merges |
| 15–20 min | Explore the sample project and its history |
| 20–28 min | Create and commit an individual recommendation |
| 28–38 min | Run and modify the Python market-test exercise |
| 38–48 min | Open a pull request for the recommendation |
| 48–55 min | Review a partner's proposal and observe a merge |
| 55–60 min | Debrief and key takeaways |

## Getting started

Students use GitHub's browser interface for version-control activities, and run one short Python script for coding practice. No prior coding experience is needed. Students need a GitHub account to make changes and participate in review. Before class, the instructor should share the repository link and specify whether students will work in individual branches with repository access or in personal forks. Each student submits a separate file named with their GitHub username to avoid editing the same proposal file. Ensure students have access to a Python 3 environment and a local copy of the script; GitHub's browser editor does not run Python. The student handout walks through the activities.

Visual Studio Code is an optional editor for the coding activity. Download it from [code.visualstudio.com/download](https://code.visualstudio.com/download). Python 3 must also be installed, or provided through a classroom coding environment.
